# Response to the independent Opus 5.5 xhigh review

## Medium findings

- M1: verified both native HistoryService implementations. They write FileId, DroppedPath and ImportedPath. The DTO/test now use fileId and accept casing variants; unknown history data remains excluded.
- M2: registration records the full tool catalogue before service/policy filtering. Unknown allow/deny names fail both transports and the CLI before startup/health checks. Tests cover a misspelled deny and a valid tool for an unconfigured service.
- M3: preview, apply validation, and the final pre-POST hook refuse active ManualImport, download scans and ProcessMonitoredDownloads. This protects a restarted server or a copy outliving the recent-submission hold. A regression simulates loss of server state while the native command remains active; another starts a native import during metadata lookup. There is still no atomic transaction against external API clients.
- M4: added the documented bootstrap SHA and explicit fork component/separator. Releases use maintainer-run release-please 17.11.2, with the original dotted config filename passed explicitly. Actions consumes the resulting published GitHub release; it does not create or approve review PRs. The fork's Actions review-approval setting remains false. Release content must be reachable from main and match the manifest; CI and publishing use the resolved commit.

## Low findings and follow-ups

- L1/L2: CI concurrency includes workflow/ref; the binary receives the bare v-prefixed version. Release tags and image tags are separate.
- L3/L5: an app-scoped reservation replaces the global network-held lock. Plans are single-use once validation starts, even on failed validation. Invalid caller input does not spend them. Other instances can proceed independently.
- L4: matching queue rows must identify the exact target, including rejecting missing/zero target ids.
- L6: native quality revision/repack/indexer metadata remains an upstream limitation. It is explicitly documented, not represented as parity; no production cutover is claimed. A separate generic upstream change can preserve those fields without expanding this source baseline further.
- L7: zero history data is omitted with omitzero.
- L8: bearer scheme matching is case-insensitive, covered by the native HTTP test. Environment references and literals are documented accurately. Deployment requires a private random token (32 bytes of entropy recommended); a length heuristic is not claimed to establish entropy.
- L9: strict YAML parsing, history limits and expanded response evidence/paths are documented as deliberate default differences.
- L10: guarded preview advertises non-idempotence. Shared optional schemas are retained for compatibility and the forbidden arguments are refused at runtime; that limitation is documented.
- L11: command receipts include queued/started/ended times, result and message; uncertain responses identify download and submission time.
- L12: startup policy/auth state and plan/submission/uncertain outcomes are logged without tokens, opaque plan IDs or source paths.
- L13: linked the actual example and configuration guide; added target-path fencing and queue target/pagination/cap, duplicate/multi-episode mapping, concurrent apply and final command-race cases. Native Telegram approval/decline/expiry validation remains a live cutover task.

## Cutover boundaries
