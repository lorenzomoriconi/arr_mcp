# Native Hermes integration

The interactive assistant connects directly to ARR MCP over verified HTTPS. The Python code in `hermes/` is a deterministic, read-only watch helper using Hermes's installed official MCP SDK; it does not replace native tool discovery or provide a general RPC bridge. The media skill is a deployment template; replace its Python placeholder with the installation's actual interpreter. Delivery chat IDs belong only in the private operator policy.

## Connection

Use a dedicated private reverse-proxy path with bearer authentication, an exact trusted TCP peer, and normal TLS hostname/CA verification. The server supports `server.path: /rpc`, `stateless: true` and `jsonResponse: true` so a POST-only appliance route works without GET/DELETE/SSE allowances. `server.allowedPeers` contains the actual proxy CIDR, not forwarded headers. Default upstream deployments retain `/mcp` and stateful transport when these options are omitted.

Use protocol `stateless`, MCP-Protocol-Version `2026-07-28`, strict redirect headers and the operating-system CA bundle. The operator pins this dedicated hostname in root-owned OS resolution to the private router address; no reverse SSH tunnel is used.

### Delegated authority and client approvals

This integration is trusted delegated automation: Hermes and its local terminal run as the same service user and can read the scoped bearer token. All token holders have the same allowlisted privileges. Neither a skill instruction nor an MCP confirmation is a security boundary against that user; a token holder can act as its own MCP client. The actual boundaries are the server tool policy, argument/plan guards, NAS container isolation and appliance network restrictions. Chat context and imported release names remain untrusted input, and the skill still requires a user request and clear agreement for material exceptions. No separate human-authenticated approval channel or terminal sandbox is claimed.

The installed Hermes native SDK client does not yet process modern InputRequiredResult retries. Therefore the example deliberately uses permissions.mode=full for its bounded catalogue, with destructive tools denied. It does not silently enable fallback=allow or pretend Telegram buttons were tested. Upstream confirm mode remains available for clients implementing the approval protocol; source/fake-Go-client tests cover accept/decline/cancel, but that mode must be compatibility-tested before using it with Hermes. Separate gateway/terminal identities and separate read-only watch credentials would be a future isolation project.

Guarded mode refuses edits to assigned quality profiles, so changing a preset means creating/configuring a separate unassigned profile named `Hermes - ...` and assigning it to one title. Existing operator presets cannot be renamed into this reserved namespace. Before cutover, check for existing profiles with that prefix. Do not point import lists, Radarr collections or Seerr defaults at reserved profiles. Add-title calls refuse routing tags and embedded searchNow; search is a separate scoped action. Native RSS can still download monitored missing items, so agree monitoring scope as well as search scope. Torrent stop/start/recheck/reannounce require one exact hash in the media apps’ native categories. Read-only torrent listings still cover the shared configured client; this is a trusted shared assistant, not per-chat data isolation. Native downloads and explicitly accepted magnet/import actions can still cause the apps’ normal replacement/cleanup behavior.

`config.hermes.example.yaml` shows the bounded tool catalogue. `downloads.guarded: true` refuses bulk torrent/movie controls, unscoped searches, arbitrary add-title roots and generic title edits; existing-title edits only assign one quality profile. `downloads.client` binds magnets and guarded imports to the configured qBittorrent endpoint and the app's own enabled client/category. The unrestricted torrent-add tool remains excluded. Exactly one enabled qBittorrent client per media app is supported by this guarded route. Endpoint host/port/TLS/base-path must match, so an unrelated instance with a matching category is refused.

Connector rollback restores code/configuration, not media files. Native upgrades and completed-download cleanup can replace/delete library or source files even with destructive tools denied. A native recycle bin or suitable snapshots are recommended for recovery; retaining existing media-management settings does not provide that recovery guarantee. This integration does not enable recycle bins or change those settings during cutover.

A qBittorrent instance already using a trusted-source authentication bypass may explicitly set authBypass: true with no username/password/API key. The client still performs the native empty login and must receive Ok.; it does not change qBittorrent's policy. Other services and mixed credentials refuse this option. Prefer ordinary credentials where the existing installation provides them.

## Deployment and rollback

1. Create a private deployment definition using `operator/compose.py`: a recorded GHCR digest, non-root/read-only container, dropped capabilities, private exact-IP port binding, no host network or host/media/admin mounts, and a Compose config with runtime environment references. Compose dollar escaping preserves literal tokens and runtime expansion. Keep credentials in the private TrueNAS app definition, outside Git.
2. Stage a separate Custom App on an unused operator-only LAN port. Keep the current connector active. Verify the actual image and native SDK discovery/read calls with `go run ./integrations/mcp-probe`; tokens and read-call/result files stay private. The probe refuses write tools and redirects.
3. Reconcile live skill/instructions and record their fingerprints. The operator-only `vm_install.install(payload)` verifies those fingerprints and idle turn leases, creates root-only backups, updates only the arr MCP config plus its scoped environment key/skill/helpers/policy/DNS entry, backs up the watcher endpoint, clears only arr's schema cache, and leaves the gateway stopped. It never receives app or NAS administrator keys. A state/skill change requires a fresh merge before installation.
4. Stop the previous connector app, move the already verified new app to the established backend port, and verify the private HTTPS route from the VM through the actual Hermes SDK. Check native discovery and all app versions, wrong tokens, peer/Host/path/method restrictions, blocked direct services, exact import preview and watch collection without a media write or a new schedule. Start the gateway and check real progressive discovery while idle. If preparation or rollback aborts after stopping without changing targets, inspect the root-only snapshot and restart the unchanged gateway manually; do not leave it silently stopped.
5. If any check fails, stop the new app, start the previous app on its unchanged endpoint, and use the root-only immediate-cutover snapshot to restore the previous client/config/helpers/skill. Rollback refuses later configuration edits rather than overwriting them; the disposable schema cache may be rebuilt by the gateway and is restored without a hash conflict. Directory ownership/mode and the endpoint file are restored too. Keep the previous app stopped after a successful cutover until the operator deliberately retires it; its data/config are the rollback path. Never automatically restore the retired SSH transport.

Native Copy-mode imports can still be followed by app-managed cleanup, relocation or later independent upgrades. Guarded mode binds scanner mappings to completed wanted torrent entries and repeats the evidence check before POST, but it does not inspect filesystem symlinks and cannot make an atomic transaction with external clients. Nonces and local submission holds are lost on restart; inspect native commands/history/state before retries.

## Local checks

Run the Go tests/checks in AGENTS.md. Run `python -m unittest discover -s integrations/hermes -p 'test_*.py' -q` and the equivalent for integrations/operator. The operator YAML test requires PyYAML. Source/fake-API approval tests are not a real Telegram button test or a real library import. No watch or media action should be created merely to verify installation.
